# Grok Usage Pet 后续发展路线图

更新日期：2026-09-07  
当前基线：v0.3.11

## 1. 当前阶段

项目已经基本完成“AI 额度桌宠”阶段的核心需求：

- 支持 SuperGrok、Grok Bot、Cursor 与 Codex 额度展示。
- 具备额度缓存、失败保护、手动刷新与低额度状态反馈。
- 具备透明桌宠窗口、拖动、气泡展开、16 向鼠标注视和多组状态动画。
- 支持主题切换、自动唤起、桌面快捷方式、应用内更新和完整卸载。
- 发布包经过离线测试、Windows 构建冒烟、安全检查和 SHA256 校验。
- 默认角色 Pip 为项目原创，可作为独立产品形象继续发展。

以个人 GitHub 小工具衡量，当前版本已经可以稳定公开使用。下一阶段的重点不再是继续堆叠额度来源，而是让桌宠在没有任何工具账号时也具有完整体验。

## 2. 产品方向

建议将产品定位调整为：

> 一只无需账号也能陪伴你的轻量桌宠，需要时还能显示 AI 工具额度。

额度能力继续保留为差异化功能，但不再支配首次启动、角色状态和所有交互。长期结构建议分为两层：

```text
Pip 桌宠核心
├── 无账号运行
├── 动作、互动、情绪与作息
├── 角色包、主题与本地个性设置
└── 可选信息模块
    ├── AI 额度
    ├── 专注计时
    ├── 时钟与休息提醒
    ├── 电量与系统状态
    └── 后续第三方扩展
```

基本原则：

1. 桌宠核心始终离线可用，不要求用户登录外部平台。
2. 工具模块按需启用，单个模块失败不得影响桌宠运行。
3. 保持轻量、低打扰，不发展成复杂 Dashboard。
4. 默认不采集遥测，不自动上传日志或互动记录。
5. 保持旧设置、旧角色和旧安装版本的升级兼容。

## 3. 推荐版本路线

### v0.4.0：桌宠核心解耦

目标：没有 Grok、Cursor 或 Codex 账号时，应用仍是一只完整桌宠。

主要内容：

- 增加“纯桌宠模式”，全部额度来源均可关闭。
- 首次启动提供“只使用桌宠”和“连接 AI 额度”两个入口。
- 没有可用额度来源时进入正常待机，不长期显示加载或失败动作。
- 从主窗口逻辑中拆出宠物状态机、互动控制器和信息模块接口。
- 明确统一动画优先级：拖动和直接互动优先，其次特殊动作、环境反应和待机。
- 迁移旧设置时保持主题、位置、额度来源和自动启动配置不丢失。

验收标准：

- 全新 Windows 用户无需任何外部账号即可启动并持续使用。
- 所有额度模块关闭后，互动、动画、更新和卸载仍正常。
- 网络不可用或额度接口失败时，桌宠体验不受阻断。
- v0.3.x 用户原地更新后无需重新配置。

### v0.4.1：互动与性格

目标：让用户关闭额度窗后仍愿意保留桌宠。

主要内容：

- 区分单击、双击、长按、快速戳、抚摸、拖动和鼠标注视。
- 增加早安、午休、困倦、夜间睡眠等本地时间行为。
- 增加伸懒腰、观察屏幕、打盹等低频随机动作。
- 在本地保存少量陪伴状态，例如相处天数、互动次数和用户偏好。
- 提供互动频率和安静时段设置，避免持续打扰。
- 保持角色行为参数可配置，为不同角色性格做准备。

验收标准：

- 互动动作不会与拖动、额度刷新、气泡展开或自动动作互相抢占。
- 随机行为有冷却时间，不连续触发，不影响鼠标操作。
- 删除本地数据或完整卸载后，陪伴状态可彻底清除。

### v0.5.0：可选信息模块

目标：保留额度特色，同时避免继续演化成单体工具面板。

主要内容：

- 将现有 AI 额度实现为第一个标准信息模块。
- 定义模块生命周期、数据刷新、错误隔离、权限说明和显示接口。
- 支持模块独立启用、禁用、排序和刷新周期设置。
- 优先尝试无需账号或低权限的本地模块：时钟、专注计时、电量与休息提醒。
- 模块状态只能触发受控的角色反应，不能直接覆盖高优先级互动。
- 所有网络模块明确列出访问端点、读取数据和本地存储内容。

验收标准：

- 任意模块崩溃、超时或返回异常数据时，其他模块和桌宠继续运行。
- 禁用模块后不再启动其网络请求、文件读取或后台任务。
- 用户能够清楚知道每个模块需要什么权限。

### v0.5.x：角色包体系

目标：把“内置皮肤”升级为可维护、可扩展的角色生态。

主要内容：

- 标准化角色包版本、作者、许可证、预览图、图集和动作元数据。
- 支持角色独立的配色、气泡样式、动作速度、性格和互动反馈。
- 提供角色包导入、校验、更新和卸载流程。
- 提供制作模板、验证器和最小示例角色包。
- 第三方角色包与主程序隔离，非法路径、超大资源和损坏图集不得被加载。

### v1.0：稳定发行

目标：形成对普通用户友好的长期稳定版本。

主要内容：

- 完成 Windows 10/11、100%/125%/150% 缩放和多显示器真机矩阵。
- 修正负坐标副屏、混合 DPI、休眠唤醒和显示器热插拔行为。
- 在条件允许时增加代码签名，降低 SmartScreen 和杀毒软件阻力。
- 评估标准安装器，同时继续提供便携 ZIP。
- 增加用户主动触发的诊断导出，并默认清除用户名、邮箱、路径、凭据和接口详情。
- 完成陌生机器的安装、首次启动、升级、回滚和彻底卸载测试。

## 4. 并行开发方案

纯桌宠模式、互动系统和可选模块可以同步推进，但需要先完成一小段共同基础工作，避免多个功能同时修改主窗口和动画调度逻辑。

### 阶段 A：共同基础

- 固定状态机、事件和动画优先级。
- 定义桌宠核心与信息模块之间的接口。
- 将设置按“桌宠”“互动”“模块”“系统集成”分类。
- 建立旧设置迁移和模块错误隔离测试。

### 阶段 B：两路并行

路线一：桌宠体验

- 纯桌宠模式。
- 首次启动引导。
- 点击、抚摸、作息和随机行为。
- 本地陪伴状态与安静时段。

路线二：模块体系

- 抽离现有 AI 额度来源。
- 实现模块开关、排序、刷新和权限说明。
- 接入时钟、专注计时或电量中的一至两个本地模块。

### 阶段 C：联合验收

- 无账号、离线、接口失败和长时间运行测试。
- 鼠标互动、拖动、气泡、随机动作和模块反馈冲突测试。
- 旧版升级、自动更新、回滚和完整卸载测试。
- 发布包内容、隐私、敏感信息和资源路径检查。

## 5. 难度与风险

| 方向 | 难度 | 主要风险 |
|------|------|----------|
| 纯桌宠模式 | 中等 | 现有角色状态与额度加载状态耦合 |
| 互动与性格 | 中高 | 多种动作同时触发时出现抢占、卡住或闪烁 |
| 可选模块体系 | 中高至高 | 拆分现有逻辑时破坏刷新、缓存或设置兼容 |
| 角色包体系 | 中等 | 第三方资源质量、版权、格式和路径安全 |
| 多屏与 DPI | 中高 | 缺少足够的真机组合与自动化窗口测试 |
| 代码签名与安装器 | 中等 | 证书成本、发布流程和后续维护成本 |

整体属于可控的中高难度演进，主要挑战是架构边界和状态冲突，而不是单个算法。先建立状态机和模块接口，可以显著降低后续并行开发成本。

## 6. 暂不优先的方向

为了保持产品轻量，以下内容暂不作为近期重点：

- 完整聊天机器人或大模型对话入口。
- 邮件、股票、新闻、复杂日历和综合信息大屏。
- 强制账号体系、云同步或跨设备社交。
- 高频通知、广告、自动遥测或后台行为上传。
- 复杂数值养成、付费道具和重度游戏化。
- 在主安装包中无限增加未经隔离的第三方角色资源。

这些方向会显著增加权限、隐私、维护和界面复杂度，并削弱轻量桌宠定位。

## 7. 近期执行清单

建议下一轮按以下顺序开始：

1. 为纯桌宠、互动和模块接口写设计说明与状态优先级表。
2. 将额度获取与宠物动画状态解除直接依赖。
3. 实现纯桌宠模式和旧配置迁移。
4. 并行实现基础互动系统与额度模块抽离。
5. 增加无账号、离线、刷新失败和动作冲突测试。
6. 在小范围陌生机器上收集首次启动与长期运行反馈。
7. 根据真实反馈决定先加强互动，还是先扩展角色包。

近期成功标准不是“功能数量更多”，而是：没有任何 AI 工具账号的用户也能理解、喜欢并长期保留这只桌宠。
